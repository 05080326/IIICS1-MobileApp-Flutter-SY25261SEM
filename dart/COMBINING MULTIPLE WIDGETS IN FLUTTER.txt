COMBINING MULTIPLE WIDGETS IN FLUTTER
Flutter applications are built by combining widgets, the core building blocks for user interfaces. Widgets are either stateless or stateful
STATELESS
a widget that does not require mutable state. It means that once created, the widget's appearance or properties don’t change during its lifetime. 
Do not change over time

Key Points:

Immutable: Stateless widgets are immutable, meaning they can’t change their properties or appearance once built. All properties are final (defined at creation and cannot be modified).

Rebuilds: Even though they’re "stateless," these widgets can still be rebuilt if they’re part of a widget tree that needs to update. For example, if the parent widget’s state changes, it might trigger a rebuild of its child stateless widgets.Common 
Uses: Stateless widgets are perfect for displaying static information, such as text labels, icons, or UI elements that don’t change based on user interactions or data updates.

Performance: Because they don’t rely on mutable state, stateless widgets are lightweight and can be more efficient than stateful widgets.

STATEFULL
 A widget that can change its state over time. This means that parts of the widget's UI can be updated based on interactions, changes in data, or any other factor that affects the widget’s appearance or behavior

Can change based on user interaction

Key Points:
Mutable State: Unlike a stateless widget, a stateful widget can hold mutable state, which allows it to change its appearance or properties in response to user actions, events, or updates in data.
Two Classes: A stateful widget in Flutter consists of two classes:
The StatefulWidget class: This is the main class where the widget is defined.
The State class: This is where the mutable state is managed. It holds properties that can be changed and defines the build method, which returns the widget’s UI based on the current state.
Rebuild Process: When the state changes (e.g., when you call setState()), Flutter will rebuild the widget by calling the build method in the State class. This process updates the widget's UI to reflect the latest state.
Common Uses: Stateful widgets are ideal for scenarios where the UI needs to respond to user input or data updates, such as buttons, forms, animations, or any dynamic content.

KEY WIDGETS FOR LAYOUT AND COMBINATION
Container
A versatile widget for styling (background color, padding, borders, etc.).
Row & Column - Arrange child widgets horizontally (`Row`) or vertically (`Column`). These are often used together for more complex layouts
Stack - Allows widgets to be layered on top of each other, useful for overlay effects
ListView - A scrollable list of widgets, ideal for creating lists of items
GridView - Displays widgets in a grid layout

Building Complex Layouts
Nesting Widgets - By combining `Row`, `Column`, and `Stack`, you can create complex layouts. For instance, a `Column` inside a `Container`, with each child as a `Row`, creates a tabular structure
Padding and Margins - Use `Padding`, `Container`, or `SizedBox` to add spacing between widgets
Padding and Margins - Use `Padding`, `Container`, or `SizedBox` to add spacing between widgets
Using Spacer - Adds flexible space between widgets in a `Row` or `Column`, making it easy to control alignment and spacing
Performance Tips - Avoid excessive nesting: Deeply nested widgets can impact performance. Consider using simpler widgets or using `const` where possible to reduce rebuilds.
 
Use const Widgets: Where possible, use `const` for widgets that don’t change to optimize rebuilds.
